# Codex Support Implementation Plan

**Goal** — Add `setup-codex`, include Codex in `setup-agents`, and make the existing `setup-agents` plugin installable from a native Codex marketplace backed by this repository.

**Architecture** — Keep one plugin and the existing scan, catalogs, language profiles, and approval flow. Add a Codex materializer alongside Claude Code and Antigravity. Treat `AGENTS.md` and `.agents/skills/` as shared outputs whenever Codex and Antigravity are both selected.

**Tech stack** — Bash, Markdown skills, JSON plugin and hook manifests, TOML Codex agents, and the existing shell fixture suite.

## Current setup

- `skills/setup-claude/SKILL.md` and `skills/setup-agy/SKILL.md` choose a target and delegate to `skills/setup-agents/references/scan-and-plan.md`. `skills/setup-agents/SKILL.md` selects both targets. `install.sh` independently implements the terminal flow, including a platform menu and separate writers.
- `plugins/setup-agents/` ships three real skill directories, a Claude manifest and an Antigravity manifest. Its seven `template/` entries are symlinks into the source tree. `scripts/materialize-agy-skills.sh` refreshes existing skill destinations and skips missing ones, so adding a source directory alone does not ship a new entry point.
- The baseline `AGENT_STARTER_NO_EXTERNAL=1 bash scripts/test.sh` passed all 17 checks, including 108 hook fixtures. An isolated Codex CLI 0.167.0 install accepted a native catalog and `.codex-plugin/plugin.json` overlay on a copy of the existing plugin. The cache omitted the symlinked templates. Reinstalling a copy with real assets made representative files from all seven template entries readable in the cache. Claude and `agy` validators also accepted the overlay. The probe exercised packaging and CLI installation. Desktop discovery and running the scaffolding skills are release checks below.

## 1. Package the existing plugin for Codex

- Create `.agents/plugins/marketplace.json` with marketplace name `agent-starter`, one `setup-agents` entry and `interface.displayName` set to `Agent Starter`. Set `source` to `{"source":"local","path":"./plugins/setup-agents"}`, policy to `AVAILABLE` and `ON_INSTALL`, and category to `Productivity`. The path is relative to the repository root. Keep the marketplace versionless. [OpenAI plugin packaging](https://developers.openai.com/plugins/build/plugins#marketplace-metadata)
- Create `plugins/setup-agents/.codex-plugin/plugin.json` with the same plugin ID, version, author, repository and license as the other manifests, a description covering three hosts and `"skills": "./skills/"`. Keep the existing Antigravity root manifest and Claude overlay. The Codex overlay is supported by OpenAI and worked with the locally installed CLI. The plugin distributes setup skills. Project hooks ship as template assets and are installed by the setup workflow when selected. [OpenAI plugin structure](https://developers.openai.com/plugins/build/plugins#plugin-structure)
- Extend `scripts/materialize-agy-skills.sh` into the bundle generator, retaining its current command and `--check` interface. Explicitly list the four setup skills and materialize readable copies of the templates under `plugins/setup-agents/template/`. Copy from canonical sources, limit the bundle to runtime assets, and exclude hook fixtures, nested packaging, and other development-only files. Ship Codex templates through the same generator. Check for missing destinations, source drift, symlinks and lost executable bits. Commit the generated package so a Git marketplace install needs no build step.
- Update `scripts/test.sh` first with a failing check for the native marketplace and expected package contents. Add an isolated CLI installation check when `codex plugin add` is available. Verify every expected skill, reference, language profile and template is readable from the installed cache, with the checkout unavailable during the asset-read check. Use the installed path returned by `--json` to accommodate cache layout differences.
